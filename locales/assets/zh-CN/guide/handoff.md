# 交接(`/handoff`)

用户在飞书里发 `/handoff`,summon 让当前 agent 把手上的工作写成一份交接文件,再交给接手方。
群里要先 @ 当前 agent;权限与 `/new` 相同(会话操作权限)。

- `/handoff [备注]`,有交互式压缩命令的会话(目前是 claude)—— 写完交接文件后在当前会话原地
  `/compact`,会话不换;压完不自动开工。写交接的指令会要求你在用户下一条消息到来时先读交接文件,
  然后按备注(或「下一步」)接着做;压缩后是否还记得这条要求取决于压缩摘要,交接文件始终在盘上。
- `/handoff [备注]`,其余会话(codex / cursor)—— 交给当前 agent 的新会话:旧会话归档(`/resume`
  可恢复),新会话的第一条消息是「先读交接文件 <路径>,然后 <备注>」。
- `/handoff @agent [备注]` —— 交给本群另一个 summon agent:summon 以发起人的身份把同一句话投给
  它,不经过 bot 之间的 @,所以两个 bot 不需要互相 `/introduce` 过;投递落盘后当前会话退出
  (保留续聊入口)。目标必须是本机 summon 管理、且 bot 在本群的 agent,发起人要在它的对话名单里,
  否则当场拒绝,什么都不写。

没写备注时,接手方被要求「按其中的「下一步」接着做」。

`/handoff` 只在本群里交接。owner 要向另一个群委派任务、只在群卡展示摘要时,由你调 `summon delegate`
(见 `summon guide protocol`「跨群委派」),不是 `/handoff`。

## 收到写交接的指令时

1. 按下面的模板写交接文件,写给一个没有任何上下文的接手人。放进工作目录下的任务目录
   `tasks/<日期-主题>/HANDOFF.md`;这件事已有任务目录就写进那里,已有交接文件就按现状更新。
2. 回复末尾单独写一行 `<summon-handoff>交接文件的绝对路径</summon-handoff>`。summon 会把这行从
   正文里拿掉;它写在 feed 总结标签之前或之后都行。
3. 写不成(缺信息、写盘失败)就说明原因、不要写这一行。

只有这一轮正常完成、标签里是这一轮写过的文件的绝对路径(带目标时目标 bot 也还在本群)summon
才交接;否则回一句「交接没写成」,不拆会话、不投递。写交接期间用户再发的消息不并进这一轮,排到
交接之后再跑:原地压缩时在压缩之后的当前会话里跑;交给新会话时在新会话里、读完交接文件之后跑;
交给别的 agent 时交还当前 agent,按退出后的续聊规则跑;没交接成就在当前会话里照常跑。

## 模板

- 目标:这件事最终要达成什么、完成条件
- 现状:做完了什么、做到一半的是什么(带 commit / 分支 / 文件位置)
- 下一步:按顺序列,第一步要具体到能直接动手
- 约束与决定:用户的纠正与裁决原话、已否决的方向
- 关键文件与命令:要读的文件、要跑的命令与测试入口
- 未验证 / 风险:没跑过的、拿不准的

## 收到交接时

第一条消息是「先读交接文件 <路径>,然后 …」;交给别的 agent 时前面还有「<谁> 把手上的工作
交接给你」。先读那份文件,再按备注或文件里的「下一步」接着做。
