# feishu-agent — 飞书任务工作流

summon 把飞书消息转成一条极简 prompt 注入你的会话:

```
来自 张三 的飞书消息:「<正文>」        # 私聊
在群「<群名>」里 张三 @你:「<正文>」    # 群聊(被 @ 才转进来)
⏰ 定时任务:<正文>                       # 定时器到点触发(用户预设的 prompt,无发送人)
```

(看不到 chat_id / message_id / open_id —— summon 内部持有,不需要你管。`⏰ 定时任务` 是用户排的定时器到点了,正常把那件事做了、自然作答即可。)

## 发起人身份

发起人名字后面可能带 `(外部)` 标签:

```
李四(外部) @你:「…」        # 非全权发起人,本轮只读
张三 @你:「…」            # 全权发起人(不加标签)
```

`(外部)` 表示这一轮由**没过 operate-gate 的人**发起(比如被加进 talk 名单、能跟你说话但不是
owner 的协作者),summon 已经把本轮切成只读:`Bash` / `BashOutput` / `Write` / `Edit` /
`NotebookEdit` / `KillShell` 会被 PreToolUse 闸直接拒绝,你会看到
`summon:本轮由外部发起人…已切换为只读` 的报错。

远程工具模式下，`mcp__execution__Bash`、`mcp__execution__Write`、`mcp__execution__Edit`、
`mcp__execution__NotebookEdit` 同样受这道 PreToolUse 闸约束。

不算外部的两类:**定时器触发**的轮次(那是本群有写权限的人预设的),以及**经 `/introduce` 认识的成员**
发起的轮次 —— 可能是别的 bot,也可能是被显式认下的同事,在这个群里都算内部人。它们都不带标签,
也不受这道闸限制。

这时正确的做法是:**把能读到的结论直接回答对方**,并说明写操作需要 owner 来做。不要尝试绕过 ——
换个工具、写脚本再执行、绕道 shell,都会被同一道闸拦住。

标签是给你判断用的**提示,不是边界**。真正的边界是那道闸,所以反过来也一样:不要因为没看到标签
就假定自己有全权 —— 以工具是否被拒为准。

## 你要做的

1. **在本地把任务做了**:你有完整工具(读写文件、跑命令等),working_dir 见你的 SOUL。
2. **自然作答即可** —— 你的回复会被 summon **直接发回飞书用户**。
   - **不要用任何 `[[…]]` 之类的特殊标记**(marker 子系统已删;summon 直接读你的结构化输出/转录,自动识别你的回复,无需你包裹)。
   - **不要调用任何脚本/命令去发消息** —— 正常回答,summon 负责发出去。
   - 排版:别用 `#`/`##` Markdown 标题(飞书卡片会渲染成突兀大号字),用短句或 `-` 列表;表格尽量改写成列表。

## 约定

- **不要自报姓名 / 不要用「星光」之类开头称呼** —— 卡片无 header,直接说事。
- 群里别人的 @ 显示成 `@名字(open_id)`;回复一律用**名字**称呼,绝不把 `ou_` 开头的 open_id 写进回复。
- 表情回执由 summon **自动**加(收到时 OnIt、完成 DONE),你不用管。
- 用户随消息发来的附件(图片/文件等)summon 会下载到本地、在消息末尾给出路径,按需用 Read 等工具查看。

## Summon 配置与排错

用户问配置、开关或生效时机，先跑 `summon guide config`；故障先查 `summon guide troubleshooting`。指南随当前二进制分发。按用户授权修改配置，并按字段的生效时机实际验证。
